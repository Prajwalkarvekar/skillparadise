# Performance verification — 28 September 2026

Measured with Lighthouse 13.4.1 on the local production build at `http://127.0.0.1:4173`, using default simulated mobile throttling and the explicit desktop configuration. Audits ran sequentially. Reports have no runtime errors or run warnings.

| Page / run | Performance | LCP | TBT | CLS |
|---|---:|---:|---:|---:|

| [Courses mobile — after](courses-after-mobile.json) | 97 | 2.5 s | 30 ms | 0 |
| [Courses mobile — repeat](courses-after-mobile-repeat.json) | 98 | 2.3 s | 10 ms | 0 |
| [Courses desktop — after](courses-after-desktop.json) | 100 | 0.5 s | 0 ms | 0.002 |

The user's score of 41 was on the Vite development server at port 5173. It is not an equivalent baseline for production: the production baseline already scored 96. The 90+ target is verified for the pages and device profiles above, not guaranteed for every page, host, network or future run.

## Changes preserving the existing appearance

- Added responsive source sizes for the same course photos, keeping their quality setting, image content, CSS crop and card design. Browser selects 480/800/1200-pixel variants according to screen size/density.
- Optimized the two existing SVG logos with SVGO, preserving their viewBox, dimensions and artwork. Each decreased from 292 KB to 102 KB; compressed size decreased from approximately 118 KB to 43 KB.
- Added intrinsic dimensions to navbar/footer logos and deferred offscreen footer-logo loading.
- Added one-year immutable Netlify cache headers for fingerprinted `/assets/*` files. This helps deployed repeat visits and is not included in the local-preview score improvement.

Courses mobile transferred 1,549,063 bytes before and 825,035 after (about 47% less). No page copy, layout classes, colors, navigation, functionality or cookie-banner behavior were changed. The before/after mobile screenshots were visually inspected; the final desktop and home screenshots were also inspected. This was not a full pixel-diff or interactive regression test.

`npm run lint` and `npm run build` passed. Lighthouse's initial CLI run wrote a valid report but hit a Windows temporary-profile cleanup error afterward; subsequent runs used isolated workspace profiles and completed successfully.

## Reproduce

From `Frontend`, run `npm run build` and `npm run preview -- --host 127.0.0.1 --port 4173`. Open `http://127.0.0.1:4173/courses` and audit in Lighthouse. Use Mobile or Desktop as appropriate; audit the production preview rather than `localhost:5173`.

Re-test the deployed HTTPS URL after hosting. Local scores do not measure CDN latency, deployed cache headers or field Core Web Vitals.
